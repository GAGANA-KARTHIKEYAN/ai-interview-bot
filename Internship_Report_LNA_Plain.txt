1. EXECUTIVE SUMMARY

During the internship period at LNA Technologies Pvt. Ltd., we designed, developed, and deployed a fully functional Intelligent AI Interview Platform — a serverless, cloud-native web application that automates technical interview sessions using Generative AI. The platform extracts candidate skills from uploaded resumes, conducts adaptive technical interviews using a four-level difficulty model, evaluates responses using Amazon Nova Lite, performs real-time behavioral analysis using Groq's Vision AI, and maintains a persistent growth ledger across sessions using AWS DynamoDB.

The project progressed through three phases — Requirements and Prototyping, Core Development, and Cloud Deployment and Testing — and culminated in a fully deployed, production-ready system on AWS. The platform represents a significant application of cloud-native serverless architecture and large language model integration for enterprise-grade interview automation.


2. INTRODUCTION

LNA Technologies Pvt. Ltd. identified a growing need in the recruitment industry for an automated, intelligent, and unbiased interview system that could reduce the time and cost of initial technical screening while providing candidates with a meaningful, growth-oriented evaluation experience.

We were assigned the task of building this platform from the ground up during the internship. The system was designed to serve both enterprise recruiters as a screening tool and candidates as a practice and growth tracking platform. The project required expertise in full-stack web development, cloud infrastructure, and large language model integration — all of which were developed and applied over the course of the internship.


3. PROJECT OBJECTIVES

The following objectives were defined at the start of the internship:

To build a serverless, scalable web platform capable of conducting automated AI-driven technical interviews.

To implement accurate resume parsing and skill extraction from PDF and DOCX formats.

To develop a four-level adaptive questioning engine that adjusts difficulty based on candidate performance in real-time.

To implement a Historical Weakness RAG (Retrieval-Augmented Generation) system that tracks and responds to individual candidate growth across multiple sessions.

To integrate real-time behavioral analysis using Vision AI to assess candidate confidence, eye contact, and professional presence.

To enforce interview integrity through multi-layer tab switching and focus detection.

To deploy the complete system on AWS using a serverless architecture for cost efficiency and scalability.


4. TECHNICAL ARCHITECTURE

The platform follows a Three-Tier Serverless Architecture.

4.1 Presentation Tier (Frontend)

Framework: Next.js 15 (React 19, TypeScript)
UI: Tailwind CSS with Framer Motion animations
Browser APIs: Web Speech API for voice transcription, MediaRecorder API for webcam capture
Deployment: AWS Amplify

4.2 Logic Tier (Backend)

Framework: FastAPI (Python 3.11)
Serverless Adapter: Mangum, which wraps FastAPI for AWS Lambda
Deployment: AWS Lambda with API Gateway using Proxy Integration
Key Libraries: pdfplumber, python-docx, boto3, pydantic

4.3 Data and Intelligence Tier

Resume Storage: Amazon S3 (bucket: ai-interview-bot-storage)
Database: AWS DynamoDB with three tables: InterviewUsers, InterviewProfiles, InterviewHistory
Primary AI: Amazon Nova Lite v1 via AWS Bedrock Converse API
Vision AI: Groq Cloud using Llama 3.2 Vision (llama-3.2-11b-vision-preview)


5. WORK PERFORMED

5.1 Phase 1 - Requirements and Prototyping (January 24 to February 14, 2026)

During the initial phase, we analysed the problem statement and defined system requirements. We studied existing interview automation research across eleven peer-reviewed papers. We set up the development environment including Node.js, Python, and Git. We built the initial prototype with Firebase authentication, local file storage, and Groq-based LLM integration. We also implemented the basic interview loop covering resume upload, parsing, question generation, and answer submission.

5.2 Phase 2 - Core Development (February 15 to March 12, 2026)

We implemented the full authentication flow using Next.js and a custom API. We built the resume parsing pipeline using pdfplumber and python-docx. We developed the AI-driven skill extraction prompt for the Groq LLM and implemented the standard interview flow with question generation and answer evaluation.

We built the multimodal input pipeline including voice transcription via the Web Speech API and video frame capture via the MediaRecorder API with Base64 encoding. We implemented the four-layer Interview Integrity System which detects tab switching via the visibilitychange API, application switching via window blur events, split-screen usage through a resize-based heuristic triggered when window width drops below 70% of screen width, and focus loss through polling every 1.5 seconds as a Chrome and Edge fallback. Interviews are automatically terminated and logged after three integrity violations.

We also built the Dashboard UI with interview history, skill cards, and score visualisation using Framer Motion.

5.3 Phase 3 - AWS Migration and Deployment (March 13 to April 21, 2026)

We migrated all storage from local JSON files to AWS DynamoDB across three tables and migrated resume file storage to Amazon S3. We wrapped FastAPI with Mangum and deployed to AWS Lambda via the Serverless Framework, and configured AWS API Gateway with Proxy Integration for all endpoints.

We replaced the Groq text LLM with Amazon Nova Lite via the Bedrock Converse API for primary reasoning, retaining Groq Cloud specifically for Llama 3.2 Vision behavioral frame analysis. We implemented the Historical Weakness RAG system with two core functions: append_history_and_extract_weaknesses which extracts missed and incorrect concepts after each answer, and get_candidate_weaknesses which retrieves past gaps before each new session. Retrieved weaknesses are injected into the Nova Lite prompt as historical context.

We redesigned the evaluation engine into a single Consolidated Prompt architecture that handles evaluation, adaptive decision, next question generation, and weakness extraction in one LLM call. We also implemented the four-level adaptive difficulty model progressing from Basic through Conceptual, Applied, and Expert levels. The phase concluded with end-to-end testing and full project documentation.


6. KEY FEATURES AND INNOVATIONS

6.1 Active Memory RAG (Primary Innovation)

The platform's most significant innovation is its Historical Weakness Retrieval-Augmented Generation system. Before each interview session, the system queries DynamoDB for the candidate's past technical failures including missed and incorrect concepts. These are injected into the AI's prompt context, enabling the bot to specifically probe known weak areas without revealing this to the candidate. This transforms the platform from a one-time quiz tool into a long-term personal career development coach.

6.2 Four-Level Adaptive Questioning Engine

The interview engine follows a structured pedagogical model with Level 1 covering basic definitions and recall, Level 2 covering conceptual understanding and internal mechanics, Level 3 covering real-world application and architecture decisions, and Level 4 covering advanced mastery, edge cases, and optimisation. The AI dynamically escalates or de-escalates difficulty based on answer quality, with a maximum of four questions per skill to prevent stagnation.

6.3 Hybrid AI Strategy

The system uses a dual AI provider approach. Amazon Nova Lite via Bedrock handles technical reasoning, evaluation, and adaptive decision-making. It was chosen for its AWS-native security, long context windows, and reliable JSON output. Groq Llama 3.2 Vision handles behavioral frame analysis. It was chosen for its LPU hardware that delivers sub-800 millisecond image inference, which is critical for maintaining a live interview feel.

6.4 Consolidated Single-Prompt Architecture

All evaluation logic including answer scoring, adaptive decision, next question generation, and weakness extraction is handled in a single LLM call. This reduces response latency by eliminating sequential API calls.

6.5 Interview Integrity System

A four-layer browser-based malpractice detection system uses the Page Visibility API, window focus events, resize-based split-screen detection, and aggressive polling. Interviews are automatically terminated and logged after three violations.

8. CHALLENGES AND SOLUTIONS

Challenge 1: AWS Lambda Statelessness

FastAPI is designed for persistent servers but AWS Lambda is stateless and loses all context after each invocation. We resolved this by using the Mangum adapter to bridge FastAPI and Lambda, and by persisting all session state to DynamoDB after every API call, enabling seamless session continuity.

Challenge 2: Prompt Blowout in RAG

As candidates completed more sessions, the weakness list grew indefinitely, causing the AI prompt to exceed token limits. We resolved this by implementing deduplication and a hard cap of 15 most recent weaknesses per skill, preventing prompt overflow while retaining the most relevant context.

Challenge 3: Video Frame Latency

Initial tests with standard cloud GPU APIs showed 3 to 5 second delays per video frame, which broke the live interview experience. We resolved this by migrating video analysis to Groq's LPU hardware using Llama 3.2 Vision, reducing frame analysis time to under 800 milliseconds.

Challenge 4: Tab Switch False Positives

API error overlays triggered window blur events, causing unintended tab-switch penalties during legitimate UI interactions. We resolved this by implementing an ignoreFocusLossRef guard and a 500 millisecond debounce to prevent cascade re-entry during error handling.

Challenge 5: Inconsistent AI JSON Output

Nova Lite occasionally returned malformed JSON or scores as strings such as "8/10", which broke the frontend score parser. We resolved this by adding multi-strategy JSON extraction using regex with fallback patterns, plus score clamping between 0 and 10 with string parsing for edge cases.
